## 1. Executive Summary

The user accessed some pages from the website "LetsDefend" one of the pages ended in the word "skills" which the SIEM flagged as the command "ls" flagging it malicious.

---

## 2. Alert Details

- **Trigger:** The user accessed the URL "https://letsdefend.io/blog/?s=skills"
- **Source Host / User / IP:** 172.16.17.46 
- **Destination Host / IP (if applicable):** 188.114.96.15
- **Timestamp of Alert:** 2022-02-27T00:36:04+03:00
- **Initial Indicators:** The "ls" at the end of the URL

---

## 3. Investigation Timeline

| Time | Action Taken | Observation |
|---|---|---|
|00:00| Reviewed initial alert in SIEM |  LS Command Detected in Requested URL, there was a foreign destination IP address as well. |
|00:02 | Checked destination IP reputation | Clean, on VirusTotal,and AbuseIPDB |
|00:05 | Checked the requested URL | Clean, on VirusTotal and HybridAnalysis |
|00:07 | Checked the logs on the host machine | Confirmed there was a communication with the destination IP address on multiple occasion. |
|00:09 | Checked the terminal history on the host machine | No 'ls' command had been executed during the time of the alert or even after it. |
|00:13| Checked the browser History of the host machine | The user accessed different "letsdefend" URLs which is the official URL.


---

## 4. Evidence & Analysis

- **Logs Reviewed:** SIEM, EDR, Browser
- **Tools Used:** VirusTotal, HybridAnalysis, AbuseIPDB
- **Key Findings:**
  - URL ends in "ls" due to the word "skills".
- **IOCs Identified:**

| Type | Value | Reputation / Source |
|---|---|---|
| IP | 188.114.96.15 | Clean, on VirusTotal and AbuseIPDB|
| URL | https://letsdefend.io/blog/?s=skills | Clean, on VirusTotal and HybridAnalysis |

---

## 5. Root Cause / Attack Vector

The user visited pages in the website letsdefend.io. The URL "https://letsdefend.io/blog/?s=skills" had the word "skill" which ended in "ls". 

---

## 6. Verdict & Justification

False Positive. After reviewing the SIEM logs, endpoint browser history and EDR logs there were no signs of any attacks.Credentials from the initial SIEM alert were also checked through different analysis tools. The results came clean in all of them, hence it can be concluded that the alert is false. 

---

## 7. Impact Assessment

- **Scope:** None
- **Data Exposure:** None
- **Business Impact:** No effect because there was no attack.

---

## 8. Response & Remediation

- **Immediate Actions:** None
- **Follow-up Actions:** Change the policies in the IDS and SIEM to ensure, regular strings are not taken as special characters.
- **Escalation:** N/A

---

## 9. Lessons Learned

A SIEM or IDS should be fined tuned to be able to handle such cases were certain strings in an address does end up being interpreted as a command or a special character.
